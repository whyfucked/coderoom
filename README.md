# CodeRoom

Локальный агент для работы с кодом — свой Claude Code / Codex для терминала и браузера.
Читает и правит файлы, запускает команды, ищет по проекту — с твоего разрешения.
Без внешних зависимостей: только Node.js ≥ 20.

**59 моделей по одному ключу:** Claude Opus 4.7 / Sonnet 5, GPT-5.6, GPT-OSS, Nemotron 3 Ultra,
DeepSeek V4, Gemini и Gemma, Qwen, GLM, Yi и др. — разложены по разделам (Anthropic, ChatGPT,
Nvidia, DeepSeek, Google, Qwen, Z-AI, 01-AI). Ключи провайдеров держит шлюз — тебе нужен только
свой ключ `cr-…`.

```
  ▗▄▄▖ CodeRoom v1.1.7
  локальный агент для кода

  ⏺ Read(src/app.js)
  ⎿ 42 строки
  ⏺ Edit(src/app.js)  +6 -2
```

## Установка

Требуется **Node.js 20+** (проверено на 22).

### Глобально (команда `coderoom` в любом cmd/PowerShell)

```bash
npm install -g coderoom-cli
```

Или из исходников / из файла:

```bash
npm install -g .                      # из папки проекта
npm install -g coderoom-cli-version.tgz # из скачанного архива
```

После этого в любом окне cmd работает:

```bash
coderoom
```

(и короткий алиас `cr`). Обновить после изменений — снова `npm install -g .`.
Удалить — `npm uninstall -g coderoom`.

> Если после установки cmd не находит `coderoom` — значит папка глобальных пакетов npm
> не в `PATH`. Узнать её: `npm prefix -g`; добавь этот путь в переменную среды PATH и открой cmd заново.

### Без установки

```bash
node bin/coderoom.mjs
```

### Собрать и выложить

В пакет входят только `bin/`, `src/`, `plugins/`, README и LICENSE — **без серверной
части, ключей и базы**.

```bash
npm test              # прогон проверок
npm pack              # → coderoom-cli-1.0.1.tgz (~455 КБ)
npm publish           # нужен npm login; тесты прогонятся автоматически
```

Раздать без npm — тем же архивом или прямо из репозитория:

```bash
npm install -g coderoom-cli-1.0.1.tgz
npm install -g github:whyfucked/coderoom
```

## Быстрый старт

Нужен ключ вида `cr-…`. Бесплатный ключ можно получить в Telegram-боте
[@coderoomfree_bot](https://t.me/coderoomfree_bot).

### Вариант 1. Интерактивный мастер

```bash
coderoom
```

При первом запуске спросит адрес шлюза (жми Enter — по умолчанию правильный),
ключ, модель и дизайн. Ключ сохранится в `~/.coderoom/config.json`
(права `0600`, только для тебя).

### Вариант 2. Переменной окружения (без мастера)

```powershell
$env:CODEROOM_KEY = 'cr-ТВОЙ_КЛЮЧ'
coderoom "почини тесты в src/"
```

```bash
export CODEROOM_KEY='cr-ТВОЙ_КЛЮЧ'
coderoom "почини тесты в src/"
```

Свой шлюз — `CODEROOM_BASE_URL=https://адрес` или команда `/gateway <url>` в диалоге.

## Как пользоваться

```bash
coderoom                          # диалог в текущей папке
coderoom "добавь тесты для utils" # выполнить задачу и остаться в диалоге
coderoom -p "как устроена авторизация?"   # ответить и выйти (без интерактива)
coderoom --plan "предложи рефакторинг"     # только чтение, ничего не менять
coderoom --web                    # интерфейс в браузере
coderoom -c                       # продолжить последнюю сессию
```

### Флаги

| Флаг | Что делает |
|------|-----------|
| `-m, --model <имя>` | модель на этот запуск |
| `-t, --theme <имя>` | дизайн терминала: `claude`, `codex`, `neon`, `dracula`, `github`, `minimal`, `matrix`, `pastel` |
| `-d, --dir <путь>` | рабочая папка (по умолчанию текущая) |
| `--mode <режим>` | `default` · `acceptEdits` · `plan` · `yolo` |
| `--plan` | то же, что `--mode plan` |
| `--yolo` | без подтверждений (осторожно) |
| `-y, --yes` | то же самое: ничего не спрашивать |
| `--update` | обновиться до свежей версии и выйти |
| `--no-update` | не проверять обновления в этот запуск |
| `-c, --continue` | продолжить последнюю сессию в этой папке |
| `-r, --resume <id>` | продолжить конкретную сессию |
| `-p, --print` | вывести ответ и выйти |
| `-w, --web` | веб-интерфейс |
| `--port <n>` | порт для веба (по умолчанию 4517) |
| `--setup` | заново пройти настройку |
| `--no-color` | без цветов |

### Слэш-команды (в диалоге)

`/help` `/provider` `/model` `/gateway` `/theme` `/mode` `/key` `/config` `/status` `/clear`
`/compact` `/diff` `/todo` `/context` `/export` `/cwd` `/sessions` `/resume <id>`
`/memory` `/init` `/skills` `/skill <имя>` `/plugins` `/ssh` `/web` `/cost` `/update` `/trust` `/exit`

Пользовательские инструкции агенту сохраняются командой `/prompt add <имя> <текст>`, переключаются через `/prompt use <имя>` и отключаются через `/prompt off`.


Плюс команды плагинов (`/commit`, `/code-review`, `/feature-dev`, …) — они в том же списке.

### Интерфейс

- **Автодополнение команд** прямо в строке ввода, с описаниями: набери `/` и выбирай `↑↓`, `Tab`/`Enter` — подставить.
- **Многострочный ввод**: `Shift+Enter` — новая строка, `↑↓` ходят по строкам и по истории.
- **Меню выбора** для `/model`, `/theme`, `/provider` — с поиском, группами и превью (тема показывает сама себя).
- **Строка состояния** под вводом: модель, режим, заполнение контекста, токены, прогресс плана.
- **Набор наперёд**: можно печатать, пока агент работает — выполнится, как освободится.
- `Shift+Tab` — переключить режим доступа, `Esc` — прервать агента, `Ctrl+C` — очистить строку (дважды — выход).
- Терминал без юникода (старый `cmd`) автоматически получает ASCII-начертание; принудительно: `CODEROOM_ASCII=1`.

## Обновления

Раз в сутки CodeRoom тихо спрашивает npm, не вышла ли версия свежее. Если вышла —
перед первым вопросом в диалоге показывает, что изменилось, и предлагает поставить.
Ответ запоминается: «позже» молчит сутки, «пропустить» — про эту версию больше ни слова,
«никогда» выключает проверку совсем.

```bash
coderoom update          # проверить и обновиться прямо сейчас
coderoom update auto     # ставить новые версии молча, без вопросов
coderoom update manual   # снова спрашивать перед установкой
coderoom update off      # не проверять обновления вообще (on — включить обратно)
```

Команда сама понимает, как установлен CodeRoom (npm/pnpm/yarn/bun, глобально или
локально), и зовёт нужный менеджер. Если запущен из исходников — просто подскажет `git pull`.
В диалоге то же самое делает `/update`.

Настройки лежат в `~/.coderoom/config.json`:

```jsonc
"update": {
  "check": true,          // проверять обновления
  "prompt": true,         // спрашивать перед установкой
  "autoInstall": false,   // ставить молча
  "intervalHours": 24,    // как часто ходить в npm
  "channel": "latest",    // канал: latest | beta
  "skipVersion": null     // пропущенная версия
}
```

Проверка не мешает работе: она с таймаутом в 5 секунд, ответ кэшируется, а если npm
недоступен — CodeRoom просто молчит и работает дальше.

## Чтобы не спрашивало каждый раз

В любом запросе на подтверждение есть пункт **«Разрешить и больше не спрашивать»** — он
превращает конкретное действие в правило и кладёт его в `permissions.allow`, так что после
перезапуска вопрос не вернётся. Правила читаемые:

| Действие | Правило |
|---|---|
| `npm run build` | `Bash(npm run *)` |
| правка файла | `Write(**)`, `Edit(**)` |
| запрос к сайту | `WebFetch(https://example.com/**)` |

Посмотреть и почистить список — `/trust` (или `/trust clear`). Разрешить всё сразу:
`/mode acceptEdits` (правки без вопросов), `/mode yolo` или запуск с `-y` / `--yolo`.
Опасные команды (`rm -rf`, `git push --force`, `curl | sh`) спрашиваются всегда, кроме `yolo`.

## Режимы доступа

| Режим | Поведение |
|-------|-----------|
| `default` | спрашивает перед правкой файлов и командами — безопасно |
| `acceptEdits` | правит файлы без спроса, команды всё равно спрашивает |
| `plan` | только чтение: исследует и предлагает план, ничего не меняет |
| `yolo` | разрешает всё (кроме `deny`-правил) — на свой страх |

Опасные команды (`rm -rf`, `git push --force`, `format`, `curl ... | sh` и т. п.)
запрашивают подтверждение **всегда**, даже в `acceptEdits`/`yolo`.

## Веб-интерфейс

```bash
coderoom --web
```

Поднимает локальный сервер на `127.0.0.1` с одноразовым токеном в ссылке
(наружу не торчит — через агента можно читать файлы и запускать команды).
Проверяется и заголовок `Host`, так что чужая страница до него не достучится.

Интерфейс собран как лента запуска: слева — проект, прошлые диалоги, живой план и
счётчик контекста; в ленте каждый шаг агента отмечен временем на общей нити, вызовы
инструментов сворачиваются в строку с длительностью, правки показываются диффом.

- **@** — подсказка по файлам проекта, **/** — команды (`/new`, `/clear`, `/model`, `/theme`, `/stop`)
- **Ctrl+K** — палитра: модели, темы, права, прошлые диалоги в одном поиске
- Подтверждения с клавиатуры: **Y** разрешить, **A** всегда, **N** отклонить
- Лента переживает F5 и обрыв связи: сервер досылает пропущенные события
- 7 оформлений: **Aurora**, **Codex**, **Terminal**, **Paper**, **Midnight**, **Sunset**, **Lime**

## Инструменты агента

`Read` · `Write` · `Edit` · `List` · `Glob` · `Grep` · `Bash` · `Todo` · `WebFetch` · `Skill` · `Ssh`

Правки файлов показываются диффом и требуют подтверждения (в `default`).
Секреты (`sk-...`, приватные ключи, токены) маскируются в выводе перед отправкой модели.
`Ssh` спрашивает разрешение всегда — даже в `acceptEdits`.

## Серверы (SSH)

Агент умеет работать на удалённой машине: `Ssh` выполняет там команды, а `/ssh` в диалоге
заводит серверы и настраивает вход. Пускают двумя способами — по ключу и по паролю.

```bash
/ssh add prod deploy@10.0.0.5:2222   # добавить сервер
/ssh setup prod                      # положить ключ CodeRoom на сервер (спросит пароль один раз)
/ssh password prod                   # запомнить пароль сервера (файл 0600, не в config.json)
/ssh auth prod key|password|auto     # чем заходить: ключ, пароль или ключ с запасным паролем
/ssh sshd prod                       # включить на сервере оба способа входа сразу
/ssh usekey prod ~/.ssh/id_ed25519   # взять свой ключ вместо созданного CodeRoom
/ssh info prod                       # что за сервер: ОС, память, что установлено
/ssh prod                            # живая сессия, «exit» — выйти
```

- Ключ CodeRoom лежит отдельно от личного `~/.ssh` — в `~/.coderoom/ssh/`.
- Пароли хранятся в отдельном файле с правами `0600`, не в общем конфиге, и маскируются в выводе.
- `/ssh sshd <имя>` правит `sshd_config` на сервере (включает `PubkeyAuthentication` и
  `PasswordAuthentication`), сохраняет копию прежнего файла и перезапускает `sshd`.
  Закрыть вход по паролю обратно: `/ssh sshd <имя> nopassword`.
- Для подстановки сохранённого пароля нужен `sshpass` (`apt install sshpass` /
  `brew install hudochenkov/sshpass/sshpass`); живая сессия `/ssh <имя>` работает и без него.

## Плагины и навыки (skills)

Совместимы с форматом плагинов Claude Code. Живут в [`plugins/`](plugins/) (встроенные),
`~/.coderoom/plugins/` (пользователя) и `<проект>/.coderoom/plugins/`. Плагин — папка с
`commands/*.md`, `skills/<имя>/SKILL.md`, `agents/*.md`.

- **Навыки (skills)** — специализированные инструкции. Агент подтягивает их сам (инструмент
  `Skill`), либо принудительно: `/skill <имя> [задача]`. Доменные навыки CodeRoom:
  **frontend-design** (красивый UI), **backend**, **testing**, **debugging**, **security**,
  **database**, **refactoring**, **performance**, **devops**, **dataviz**, **explain**
  — плюс навыки из плагинов Claude Code.
- **Команды** плагинов работают как слэш-команды: `/commit`, `/code-review`, `/feature-dev`,
  `/create-plugin` и др. Тело команды — промпт агенту (с подстановкой `$ARGUMENTS` и выполнением
  контекстных `` !`cmd` ``).

Списки: `/skills`, `/plugins`. Например, для фронтенда: `/skill frontend-design сделай лендинг`
— агент получит дизайн-гайд и задачу вместе.

## Память проекта

Агент читает при каждом запуске (если есть):

- `~/.coderoom/CODEROOM.md` — личные глобальные заметки
- `CODEROOM.md`, `.coderoom/CODEROOM.md`, `CLAUDE.md`, `AGENTS.md` в корне проекта

Создать шаблон для текущего проекта: команда `/init`.

## Безопасность

- Ключ хранится в `~/.coderoom/config.json` с правами `0600`.
- По умолчанию агент заперт в рабочей папке (`security.restrictToWorkspace`).
- Заблокированы к чтению/записи: `.env`, `id_rsa`, `*.pem`, `*.key`, `credentials.json` и т. п.
- Веб-сервер слушает только локалхост и требует токен.

Всё настраивается в `~/.coderoom/config.json`.

## Разработка

```bash
npm test            # дымовой тест: 40+ проверок, сеть не дёргает
npm run test:update # обновления и правила доступа (свой npm-реестр в temp)
```

Структура:

```
bin/coderoom.mjs     точка входа CLI
src/
  config.mjs         конфиг, пресеты провайдеров, env-переменные
  onboarding.mjs     мастер первого запуска
  provider.mjs       общение с API: стриминг, вызовы инструментов, ретраи
  agent.mjs          цикл «модель → инструменты → модель»
  tools.mjs          инструменты (Read/Write/Edit/Bash/…)
  permissions.mjs    права доступа, песочница, опасные команды
  update-checker.mjs проверка npm, установка новой версии, «позже/пропустить»
  session.mjs        история, сохранение, продолжение сессий
  themes.mjs         5 тем терминала + 7 тем браузера
  render.mjs         markdown→ANSI, диффы, спиннер, рамки
  repl.mjs           интерактивный терминал
  web.mjs            локальный веб-сервер: SSE, история событий, поиск файлов
  web-client.mjs     сборка страницы из web-ui/
  web-ui/            client.css + client.js — сам интерфейс
test/smoke.mjs       проверки без сети
test/update.mjs      обновления и «больше не спрашивать»
```

Проверить связку с живым API (нужен ключ):

```bash
CODEROOM_KEY='cr-...' coderoom -p "скажи привет одним словом"
```
