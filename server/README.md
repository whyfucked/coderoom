# CodeRoom Gateway (сервер)

Самодостаточный API-шлюз. Через него идут **все** запросы клиентов: он выдаёт ключи
`cr-…`, проверяет их и проксирует к апстримам (AgentRouter / HCN), подставляя их реальные
ключи. Клиент апстрим-ключи не видит; на каждый ключ считается расход токенов и можно
поставить лимит.

Папка не зависит от остального проекта — можно целиком поставить на домен/VPS.

```
server/
  gateway.mjs     вся логика (HTTP, ключи, прокси, админка) — без внешних зависимостей
  db.mjs          хранилище на SQLite (node:sqlite): ключи, расход, история чатов
  server.mjs      точка входа: читает .env, поднимает шлюз и бота
  bot.mjs         телеграм-бот: ключи, расход, история переписки
  keys.mjs        управление ключами и чатами из терминала
  .env            токены апстримов и бота (НЕ коммитить)
  .env.example    шаблон
  data/           coderoom.db — база с ключами, расходом и чатами (gitignore)
```

## База данных

Ключи и учёт токенов лежат в **`server/data/coderoom.db`** — SQLite через встроенный
`node:sqlite`, без внешних зависимостей. Режим WAL: запись транзакционная, ничего не теряется
при обрыве и при параллельных запросах.

- Таблица `keys` — выданные ключи `cr-…` (метка, лимит, суммарный расход).
- Таблица `usage_log` — каждый запрос: модель, апстрим, токены, время. Отсюда статистика.
- Таблица `chats` — переписка: запрос, ответ, статус, время ответа, ip. См. раздел 5.

Старый `keys.json` мигрирует автоматически при первом запуске (файл станет `keys.json.migrated`).
Если Node слишком старый и `node:sqlite` недоступен, шлюз прозрачно откатится на JSON.

Посмотреть расход:

```bash
node keys.mjs status    # ключи, апстримы, топ моделей
node keys.mjs stats     # разбивка по моделям + последние запросы
```

## 1. Токены

Скопируй `server/.env.example` → `server/.env` и впиши ключи:

```
SEEKAI_API_KEYS=sk-one,sk-two,sk-three  # claude, gpt, gemini, grok
HCNSEC_API_KEYS=sk-one,sk-two          # auto, DeepSeek, Qwen, GLM, Kimi, Step, MiniMax…
NVIDIA_API_KEYS=nvapi-one,nvapi-two    # Nemotron
# NVIDIA_ENABLE_THINKING=0   # выключить режим размышления у моделей NVIDIA
CODEROOM_GATEWAY_PORT=8787
CODEROOM_GATEWAY_HOST=127.0.0.1
# GATEWAY_ADMIN_TOKEN=длинная-строка    # иначе токен админки новый при каждом старте
```

Ключи в `*_API_KEYS` можно разделять запятыми или пробелами в одной строке. Шлюз
распределяет запросы round-robin. Если ключ получил `401`, `403`, `429` или временную
ошибку апстрима, текущий запрос автоматически перейдёт на следующий ключ.
Старый формат `SEEKAI_API_KEY=...` и аналогичные одиночные переменные тоже поддерживаются.

## 2. Запуск

```bash
cd server
npm start          # = node server.mjs
```

Печатает адрес API, ссылку на веб-админку (с токеном) и первый ключ `cr-…`.

## 3. Ключи

В браузере — через админку `http://<host>:<port>/admin?token=…`, либо из терминала:

```bash
node keys.mjs new --label "телефон" --limit 200000   # 0/без = безлимит
node keys.mjs ls
node keys.mjs rm <id>
node keys.mjs on <id> / off <id>                     # включить / выключить
node keys.mjs status
node keys.mjs stats                                  # расход по моделям
```

## 4. Телеграм-бот

Управление шлюзом с телефона: ключи, расход, история переписки.

1. Возьми токен у [@BotFather](https://t.me/BotFather).
2. Впиши в `server/.env`:

```
TELEGRAM_BOT_TOKEN=123456789:AA...
TELEGRAM_ADMIN_IDS=твой_id
```

Свой id не знаешь — оставь `TELEGRAM_ADMIN_IDS` пустым, напиши боту `/start`, он ответит
твоим id. Впиши и перезапусти.

Бот поднимается вместе со шлюзом (`npm start`) или отдельно: `npm run bot`.

| команда | что делает |
|---|---|
| `/keys` | список ключей, кнопками — карточка, вкл/выкл, удалить |
| `/new метка 100k` | новый ключ (лимит можно `100k`, `2m` или числом) |
| `/rm id` · `/on id` · `/off id` | удалить, включить, выключить |
| `/stats` · `/health` | расход, топ моделей, состояние апстримов и базы |
| `/chats` | последние чаты; кнопкой — весь текст запроса и ответа |
| `/chat 42` | конкретный чат целиком |
| `/find текст` | поиск по запросам и ответам |
| `/clearchats` | стереть всю историю (спросит подтверждение) |

Чужим бот не отвечает ничем, кроме их же id.

## 5. История переписки

Шлюз пишет в таблицу `chats` каждый запрос: модель, апстрим, статус, время, токены,
текст запроса и ответ (ответ собирается прямо из SSE-потока). Смотреть — в боте
(`/chats`), в админке (карточка «Чаты») или из терминала:

```bash
node keys.mjs chats 20     # последние 20
node keys.mjs chat 42      # весь диалог
node keys.mjs rmchats      # стереть всё
```

Длинные тексты обрезаются при записи (запрос 4k, ответ 8k, переписка — последние
сообщения до 40k символов), так что база не растёт бесконтрольно.

Выключить логирование: `CODEROOM_LOG_CHATS=0`.
Автоочистка: `CODEROOM_CHAT_KEEP_DAYS=30` — при старте удалит записи старше 30 дней.

## 6. Клиент

В клиенте `coderoom` провайдер уже `coderoom`. Указываешь URL шлюза и ключ `cr-…`
(мастер спросит), либо `set CODEROOM_KEY=cr-...`. Маршрут по модели:
`claude-*`/`gpt-*` → AgentRouter, остальное → HCN. Нет ключа у апстрима — шлюз честно
скажет, какой env добавить.

## 7. Деплой на домен

1. Скопируй папку `server/` на сервер (нужен только Node ≥ 20).
2. Положи `server/.env` с боевыми ключами; поставь `CODEROOM_GATEWAY_HOST=0.0.0.0` и
   фиксированный `GATEWAY_ADMIN_TOKEN`.
3. Запусти под процесс-менеджером (pm2/systemd): `node server.mjs`.
4. Спрячь за reverse-proxy с TLS (nginx/Caddy) на своём домене.
5. Клиентам раздаёшь `https://твой-домен` + их ключ `cr-…`.
# Публичный бот

Добавь `TELEGRAM_PUBLIC_BOT_TOKEN` в `.env`. Отдельно запускать бот не нужно:
`npm start` поднимает gateway, админ-бота и публичного бота одним процессом.
